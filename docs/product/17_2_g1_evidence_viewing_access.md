# PR17.2G1 Evidence Viewing Access

> **Status:** Implemented slice contract.
> **Scope:** Attached workflow evidence can be viewed by authorized users through the existing private `workflow-evidence` Storage RLS boundary.

PR17.2G1 is the first implementation slice of the PR17.2G plan. It does not add OCR, provider calls, review states, new workflow notifications, AI context feed, or a storage janitor. It only makes already-attached evidence visible to users who are allowed to read it.

## Product Contract

- Leave, expense, and contract records may show compact evidence actions when attached files exist.
- The action opens a short-lived signed URL generated by the authenticated browser client.
- The UI never renders storage paths and never creates public URLs.
- If Storage RLS denies access, the signed URL request fails and the user sees a generic localized error.
- G1 does not claim evidence content was scanned, reviewed, OCR-read, or validated by a provider.

## Read Model

The frontend uses existing domain metadata tables:

- `puls_workflow.leave_documents`
- `puls_workflow.expense_receipts`
- `puls_workflow.contract_files`

Rows are fetched through authenticated RLS. The shared adapter normalizes them into `WorkflowEvidenceAttachment`:

- id
- domain
- parent id
- original file name
- MIME type
- file size
- uploaded-by employee id
- attached timestamp
- scan status fallback
- private storage bucket/path for signed URL generation only

The storage path is an implementation detail. It may be held in memory by the adapter/component but must not be shown, copied, logged, sent to notifications, or added to AI context.

## UI Surfaces

- `/izin`: history and pending approval rows show a compact document action when evidence exists.
- `/masraf`: recent claim and pending approval rows show a compact receipt/document action when evidence exists.
- `/sozlesmeler`: detail sheet shows compact document action for attached contract files.

The UI remains dense and operational. No release notes, setup explanations, OCR teaser expansion, or large document panels are added.

## Security Boundary

- Uses the existing private `workflow-evidence` bucket.
- Uses existing `workflow_evidence_objects_select` Storage RLS via Supabase `createSignedUrl`.
- Recommended signed URL TTL is 120 seconds.
- No `getPublicUrl`.
- No SECURITY DEFINER signed-url RPC.
- No direct table writes.
- No raw file bytes in app state beyond the browser opening the Storage signed URL.

## Non-Goals

- OCR or structured parsing.
- Human review decision state.
- Provider/vendor selection.
- Service-role janitor for orphaned objects.
- Evidence view compliance audit. Best-effort view audit remains a later product decision.
- Notification events for evidence viewed/opened.
- AI context feed.

## Acceptance Criteria

- `WorkflowEvidenceViewActions` opens attached files through `createWorkflowEvidenceSignedUrl`.
- `createWorkflowEvidenceSignedUrl` uses `supabase.storage.from(...).createSignedUrl(..., 120)`.
- Leave, expense, and contract overview models include evidence attachment lists without exposing paths in visible UI.
- The UI has localized view/open and failure text.
- `getPublicUrl` is not used.
- Existing PR17 verify gates stay green.
